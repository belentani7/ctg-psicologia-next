    # --- MOTOR IRPF (Autónomo / RRHH) ---
    def calcular_irpf_autonomo(self, rendimiento_neto_anual):
        """Calcula IRPF según escala estatal 2024 (Ley 35/2006)"""
        tramos = [
            (12450, 0.19),
            (20200, 0.24),
            (35200, 0.30),
            (60000, 0.37),
            (300000, 0.45),
            (float('inf'), 0.47)
        ]
        
        cuota = 0
        base_anterior = 0
        
        for limite, tipo in tramos:
            if rendimiento_neto_anual > limite:
                cuota += (limite - base_anterior) * tipo
                base_anterior = limite
            else:
                cuota += (rendimiento_neto_anual - base_anterior) * tipo
                break
                
        return round(cuota, 2)

    *   Integrar librería `ReportLab` o `WeasyPrint` (si se permite HTML interno para PDF, aunque para pura natividad se recomienda `FPDF2` en Python) para generar los PDFs de las facturas y resúmenes de modelos.
5.  **Fase 5: Empaquetado (Semana 8)**

### 6. GLOSARIO TÉCNICO-LEGAL

*   **Base Imponible (BI):** Magnitud monetaria que resulta de la cuantificación de los hechos imponibles (Art. 50 LGT).
*   **Cuota Líquida:** Resultado de aplicar a la base imponible el tipo de gravamen y practicar las deducciones (Art. 55 LGT).
*   **Modelo 130:** Pago fraccionado del IRPF para autónomos en estimación directa. Representa el 20% del rendimiento neto (Ingresos - Gastos).
*   **SII (Suministro Inmediato de Información):** Sistema de la AEAT que obliga a registrar facturas electrónicamente en un plazo de 4 días. *El sistema local debe generar el XML/CSV compatible con el SII.*
*   **RETA:** Régimen Especial de Trabajadores Autónomos. Reformado por el RD-ley 13/2022 para cotizar por ingresos reales a partir de 2023.

### 7. REFLEXIÓN PROSPECTIVA Y PREGUNTA GUÍA

**Reflexión:** La transición hacia el *Software Soberano Local* (como el propuesto, compilado en Python y almacenado en SQLite) representa una reacción necesaria frente a la SaaS-ización de las herramientas fiscales. Mientras que las plataformas en la nube (SaaS) ofrecen actualizaciones automáticas de la normativa, sacrifican la privacidad de los datos financieros corporativos. Un sistema local exige que el usuario o su gestor asuman la responsabilidad de actualizar los "tramos" anualmente (vía archivos de configuración JSON), pero garantiza que la información sensible de la SL o la Cooperativa nunca salga del disco duro físico, mitigando riesgos de ciberseguridad y cumpliendo estrictamente con el principio de minimización de datos del GDPR.

**Pregunta Guía:**
*Considerando que la normativa fiscal española (especialmente los tramos autonómicos del IRPF y las deducciones del IS) cambia anualmente mediante Leyes de Presupuestos Generales, ¿cómo diseñarás el sistema de inyección de dependencias (o archivos de configuración externos) para que el usuario final pueda actualizar las reglas de negocio sin necesidad de recompilar el ejecutable de Python ni modificar el código fuente?*
