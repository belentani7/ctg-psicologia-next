## 7. GLOSARIO TÉCNICO-PSICOLÓGICO

| Término | Definición | Aplicación en ForgeUI |
|---|---|---|
| **Stroyteelonig** | Neologismo: story + telling + longevity | Framework de narrativa duradera del producto |
| **Pattern Extraction** | Análisis automático de características recurrentes en componentes | Núcleo del generador autoconsciente |
| **Harmony Score** | Métrica 0-100 de coherencia visual (color/spacing/type/motion) | Badge visible en cada ComponentCard |
| **Edge Function** | Código ejecutado en CDN, no en servidor central | API zero-cost de ForgeUI |
| **IndexedDB** | Almacenamiento persistente en navegador | Sustituye backend cuando está "sin API" |
| **Von Restorff Effect** | Mejor memoria de elementos aislados | CTAs emerald únicos |
| **Hick's Law** | Tiempo decisión ~ log(opciones) | Máximo 5 categorías visibles |
| **Gestalt Proximity** | Elementos cercanos = grupo percibido | Grid de componentes con gaps consistentes |
| **Fitts's Law** | Tiempo alcanzar objetivo ~ log(distancia/tamaño) | Botones instalación grandes |
| **Major Third Scale** | Escala tipográfica 1.25 | Jerarquía visual armoniosa |
| **Spring Physics** | Animaciones basadas en masa/resorte | Movimiento natural coherente |
| **WCAG Contrast** | Ratio mínimo 4.5:1 AA | Accesibilidad cromática |
| **Website Carbon** | g CO₂ por visita | Métrica sostenibilidad |
| **Static Export** | HTML/CSS/JS pre-generado | Deploy en GitHub Pages gratis |
| **Tree-shaking** | Eliminación código no usado en build | Bundle mínimo |
| **Dark Mode OLED** | Pixeles apagados = negro puro | -30% consumo energético |
| **Feedback Loop** | Output realimenta input | Sistema autoconsciente |

## 8. SESGOS IDENTIFICADOS Y NIVEL DE CERTEZA

| Sesgo potencial | Mitigación |
|---|---|
| **Over-engineering** (añadir generador sin necesidad real) | Validar con usuarios: ¿generan componentes? Si no, deprecar |
| **Psicología pop** (aplicar principios superficialmente) | Cada principio mapeado a métrica cuantificable (A/B testing futuro) |
| **Vendor lock-in** (Prisma + Vercel) | Prisma migrable a Postgres; deployable en 3 CDNs |
| **Sesgo de novedad** (Edge Functions vs simples APIs) | Evaluar si Edge aporta valor real vs complejidad |
| **Green-washing** (decir sostenible sin métricas) | Medir con Website Carbon Calculator mensualmente |

**Nivel de certeza**:
- Arquitectura Zero-Cost: **95%** (basado en casos Vercel/Cloudflare documentados)
- Autoconciencia sin LLM: **85%** (pattern extraction funciona; límite en complejidad)
- Branding psicológico efectivo: **70%** (principios validados, impacto subjetivo)
- Sostenibilidad medible: **90%** (métricas Website Carbon estándar)

## 9. REFLEXIÓN PROSPECTIVA (2026-2030)

**Tendencias que afectarán ForgeUI**:

1. **WebGPU (estándar 2023, adopción 2026)**: generadores visuales en cliente sin backend → ideal para "autoconciencia" real.
2. **AI-on-device (WebLLM, MediaPipe 2024)**: LLMs corriendo en navegador → posible añadir capa LLM local sin coste.
3. **Sovereign Cloud EU (2025+)**: demanda de sistemas sin APIs US → ForgeUI client-first cumple nativamente.
4. **Carbon-aware SDKs (2026)**: librerías que miden huella en tiempo real → integrar en cada build.
5. **Design Tokens Universales (W3C 2024)**: interoperabilidad entre sistemas → ForgeUI puede exportar a Figma, Style Dictionary.

**Escenario 2030**: ForgeUI evoluciona a **sistema operativo de UI** donde cada proyecto importa patrones vivos que mutan según el ecosistema global de componentes (federation tipo ActivityPub para design systems).

**Riesgo existencial**: si OpenAI/Anthropic lanzan generadores perfectos gratuitos, el valor diferencial de ForgeUI debe migrar a **curación humana + armonía cuantificada + identidad narrativa**, no a generación bruta.

## 10. PREGUNTA GUÍA PARA LA SIGUIENTE ITERACIÓN

> **Si ForgeUI fuera un organismo vivo cuyo metabolismo es el feedback de sus usuarios, ¿qué órgano sensorial le falta hoy para detectar su propia evolución antes de que los patrones colapsen por entropía?**

Esta pregunta obliga a:
- Definir **métricas de entropía** del sistema (diversidad de patrones, score promedio, dispersión)
- Implementar **alertas automáticas** cuando la armonía global decae
- Construir **mecanismos de poda** (deprecar componentes Golden que ya no son golden)
- Convertir la "autoconciencia" en **homeostasis algorítmica**, no solo en memoria
